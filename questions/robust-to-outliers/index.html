Question 1 RobustnessVery common

How do you make a model more robust to outliers?

The 30-second answer

First I'd find out whether the outliers are errors or real rare events. I'd fix or drop errors and keep real extremes. Then I'd limit how much any single point can pull the model: transform or clip skewed features, scale with the median and interquartile range (IQR), and swap mean squared error (MSE) for Huber or mean absolute error (MAE) loss. Tree-based models help with odd feature values. Finally I'd evaluate with MAE as well as root mean squared error (RMSE) and look at the worst residuals.

Start here

First question: error, or a real rare event?

"Outlier" covers two very different things, and the right fix depends on which one you have. A sensor reading of −999 is an error. A $40,000 purchase in a fraud dataset is probably the most important row you have.

👉

Sometimes the outliers are the task. In fraud or anomaly detection you don't make the model ignore them. You model them directly, for example with Isolation Forest or class weighting.

Layer 1 · the data

Find them, then decide what to do

For a single feature, simple rules work. When a point is only odd as a combination of features (a 1.9 m tall person weighing 40 kg), you need a multivariate method.

Then handle them

  • Remove only when you're confident it's an error, and record how many rows you dropped.
  • Clip (winsorize) to, say, the 1st and 99th percentiles. You keep the row but cap its pull.
  • Transform skewed features with log, Box-Cox or Yeo-Johnson. After the transform, a heavy tail stops looking extreme.
  • Scale robustly with RobustScaler (median and interquartile range) instead of StandardScaler (mean and standard deviation).
  • Rank or bin with QuantileTransformer, so only the order of values matters.
⚠️

Compute percentiles and scalers on the training set only. Fitting them on all the data leaks test-set information into training.

Layer 2 · the loss function

Stop squaring big errors

This is often the single biggest improvement. Mean squared error (MSE) squares each error, so one point that's 10 units off counts as much as 100 points that are 1 unit off. The model bends toward that one point.

Robust losses grow more slowly for large errors, so a far-off point still counts, just not quadratically.

Classification: outliers are usually wrong labels

In classification, the outliers that hurt are usually mislabeled examples. Cross-entropy pushes hard to fit them. Options: label smoothing, generalized or symmetric cross-entropy, and small-loss selection methods such as co-teaching. Focal loss up-weights hard examples, so it can make label noise worse.

Layer 3 · the model

Some models barely notice outliers

An important distinction: an outlier in the features (X) isn't the same as an outlier in the target (y). Trees are robust to the first kind, but not automatically to the second.

Layer 4 · the training loop

Don't let one batch steer the model

  • Regularisation (L1/L2, dropout) stops the model bending to fit individual points.
  • Gradient clipping caps the update size when an outlier-heavy batch produces a huge gradient.
  • Sample reweighting down-weights high-loss points. Iteratively reweighted least squares (IRLS) does this for linear models.
  • Bagging and ensembles average out the influence of any single point.
  • Early stopping: networks fit clean patterns first and memorise noisy points late in training, so stopping early leaves the noise out.
Layer 5 · how you measure it

Root mean squared error (RMSE) alone can mislead you

RMSE is itself sensitive to outliers. A model can look worse on RMSE because of three rows while being better for 99% of users, or the other way round.

  • Report MAE and median absolute error (MedAE) next to RMSE.
  • Sort by residual and look at the worst 20 rows. They often reveal a data bug.
  • Check whether the outliers all ended up in train or all in test. Stratify or split by time if needed.
  • If the extremes matter to the business, evaluate them as a separate slice.
