Question 1

How do you make models more robust to outliers?

Answer

There are four places to deal with outliers: the data, the loss function, the model, and the training process. Which one fits depends on whether your outliers are bad data (sensor glitches, typos, mislabels) or real rare events you still need to predict.

  1. Data: find them and handle them
  2. Loss function
  3. Model choice
  4. Training process
  5. Evaluation
  6. A practical default

1. Data: find them and handle them

  • Detect them: z-scores or IQR fences for a single feature. For several features at once, use Mahalanobis distance, Isolation Forest, Local Outlier Factor or One-Class SVM.
  • Remove them: only when you're confident they're errors. Deleting real extremes hides risk.
  • Clip them (winsorize): cap values at a percentile, for example the 1st and 99th.
  • Transform skewed features: use log, Box-Cox or Yeo-Johnson. A heavy tail stops looking extreme after the transform.
  • Scale robustly: use RobustScaler (median and IQR) instead of StandardScaler, because outliers distort the mean and standard deviation.
  • Bin the feature or use rank/quantile transforms: then only the order of values matters, not their size.

2. Loss function: often the biggest single improvement

Squared error (MSE) penalizes errors quadratically, so a few outliers dominate training. Alternatives:

  • MAE / L1 loss: predicts the median, so it's robust, but its gradient isn't smooth at zero.
  • Huber loss: quadratic for small errors and linear for large ones. It's the usual default. In PyTorch it's nn.HuberLoss; SmoothL1Loss is the same idea.
  • Log-cosh: a smooth version of Huber.
  • Quantile (pinball) loss: predicts a chosen quantile instead of the mean.
  • Tukey's biweight / Cauchy loss: errors beyond a threshold barely move the fit. These are strongly robust but non-convex.
  • For classification with noisy labels: generalized cross-entropy, symmetric cross-entropy, label smoothing, or focal loss used with care, since focal loss can also amplify mislabeled hard examples.

3. Model choice

  • Tree-based models (random forests, gradient boosting) are largely unaffected by outliers in the input features, because they split on order. Outliers in the target still matter, so pair them with a robust loss: XGBoost and LightGBM support Huber and quantile objectives.
  • Robust linear regression: HuberRegressor, RANSACRegressor and TheilSenRegressor in scikit-learn.
  • Distance-based models (k-NN, SVM, k-means) are sensitive. Scale robustly first, or use k-medoids instead of k-means.
  • Bayesian models: use a heavy-tailed likelihood such as Student-t instead of a Gaussian.

4. Training process

  • Regularization (L1/L2, dropout) stops the model from bending to fit individual points.
  • Gradient clipping keeps outlier batches from causing destabilizing updates in neural networks.
  • Sample reweighting: down-weight high-loss points (iteratively reweighted least squares), or use small-loss selection such as co-teaching for noisy labels.
  • Ensembling and bagging average out the influence of any single point.
  • Early stopping: networks memorize noisy or outlier examples late in training.

5. Evaluation

  • Report robust metrics (MAE, median absolute error) next to RMSE.
  • Look at how errors are spread across the data, not just the average. Inspect the worst residuals.
  • Check that your train/test split doesn't put all the outliers on one side.

A practical default

  1. Plot the data and work out whether the outliers are errors or real events.
  2. Fix or remove errors. Keep real extremes.
  3. Use RobustScaler or a log transform on skewed features.
  4. Train with Huber loss (or use gradient-boosted trees with a Huber objective).
  5. Compare against your MSE baseline using MAE and a look at the residuals.
